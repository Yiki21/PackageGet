# Iteration 070：1.3.0 P2 可靠性与可用性功能发布

- 日期：2026-10-07
- 状态：进行中（发布提交已就绪，tag 待 owner 批准）
- 主题：1.3.0 功能发布（P2 可用性能力 + 两轮正确性修复 + macOS arm64-only）

## 目标

在不改写既有稳定 tag 和 Release 的前提下，把 main 上已合并的两轮修复与本
轮的可用性能力发布为 `1.3.0`：

- 无法搜索的数据源新增按名称安装（以及 Nix 场景的按行更新）；
- 慢数据源加载期间展示已到达的结果，并提供「停止等待」控件；
- 启动后与定时后台更新检查（只读，不触发特权刷新，不产生写操作）；
- Updates 每个数据源的最后检查时间与失效计数标记；
- 浅色主题次要/警告/错误文本达到 WCAG AA；
- 第一轮（issue #14–#24）与第二轮（issue #25–#41）的全部正确性修复；
- macOS 产物自本版本起只构建 arm64（Apple Silicon），Intel Mac 停留在
  `1.2.2` 的独立不可变 tag。

本版本不新增 Package Manager，不改变 manager capability 或持久化配置协议，
继续复用 15 项产品资产与一个 `SHA256SUMS` 的跨平台发布合同。

## 行为边界

- 版本提升不改变任何运行时行为：本轮发布提交只包含版本字面量、README、
  release notes 与迭代文档，不改动 Rust 源码，测试期望值零变化。
- 继续采用既有 unsigned 政策；签名、Apple notarization 与证书 secrets 不
  作为本版本门禁。
- 不移动、删除、重打或重新上传既有稳定版资产；`1.3.0` 使用独立 tag、Release
  与 checksum manifest。`1.2.2` 的 Intel macOS 资产保持原样可下载。
- tag 发布前不执行真实 package manager 写事务；测试和原生 CI 只运行离线
  contract、只读 smoke 与受控 fake CLI。
- 后台更新检查是只读 `list_updates(.., refresh = false)`，不触发特权元数据
  同步、不弹状态面板、不占用侧边栏 loading 字形；首次访问数据页仍读取真实
  package manager 状态。
- 「停止等待」只结束等待：底层调用继续跑到自身超时，迟到的结果由既有
  request-id 守卫丢弃。
- 发布资产为 DEB/RPM/Arch、glibc/musl tar、AppImage、Windows zip/setup 与
  macOS arm64 app/dmg 共 15 项，另附一个 `SHA256SUMS`。

  `1.3.0`。

  交由 tag 的 Package workflow 验证。
